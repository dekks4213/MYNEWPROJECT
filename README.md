# Fit Coach

Самостоятельно размещаемый Telegram-бот для дневника питания и тренировок. Многопользовательский с первого дня: у каждого пользователя свои записи, изоляция обеспечивается и кодом, и row-level security в PostgreSQL. Интерфейс на русском (по умолчанию) и английском.

Бот — дневник и помощник в привычках, а не врач: он не ставит диагнозов и не рассчитывает «норму» автоматически.

## Что работает сейчас (фаза P0)

- Онбординг с возобновлением: язык, подтверждение 18+, согласие на ИИ, часовой пояс (IANA), единицы, цель, ручная цель по калориям.
- Еда вручную: пошагово или одной строкой `Овсянка; 350; 12/6/50`. Неизвестные значения не считаются нулём.
- Вес, сводка за день, исправление калорий (с защитой от одновременного редактирования), удаление и восстановление записей.
- Конструктор активностей без миграций: свой вид активности, поле длительности и любые поля (число, целое, время, выбор, да/нет, текст), шаблоны с плановыми значениями, план на сегодня/завтра, запись фактического выполнения.
- ИИ-шлюз: `disabled` / `mock` / `gemini`. ИИ только предлагает черновик, сохранение — после подтверждения. Без ИИ работает всё.

Подробности и ограничения — в [docs/STATUS.md](docs/STATUS.md).

## Быстрый старт (Docker Compose)

Нужны Docker с Compose v2 и токен бота от [@BotFather](https://t.me/BotFather).

```bash
cp .env.example .env
# заполните пароли (openssl rand -hex 24) и BOT_TOKEN
make dev          # docker compose up -d --build: БД, миграции, бот
make logs
```

По умолчанию бот работает в режиме polling — внешний адрес не нужен. Порт базы наружу не публикуется.

### Режим webhook

1. Настройте HTTPS reverse proxy на хосте (nginx, Caddy и т. п.) на `http://127.0.0.1:8080`.
2. В `.env`: `BOT_MODE=webhook`, `WEBHOOK_BASE_URL=https://ваш-домен`, `WEBHOOK_SECRET` — случайная строка от 32 символов.
3. `make dev`. При старте бот регистрирует вебхук `…/telegram/webhook` и проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.

Одновременно для одного токена может работать только один получатель обновлений: не запускайте polling и webhook вместе.

### ИИ (необязательно)

- `AI_PROVIDER=mock` — тестовый режим без внешнего провайдера; ответы помечаются в интерфейсе.
- `AI_PROVIDER=gemini` — требует `GEMINI_API_KEY` и `GEMINI_MODEL`. Модель укажите сами, предварительно проверив её доступность для вашего ключа и региона, а также условия обработки данных. Адаптер ещё не проверен на живом API (см. STATUS).
- Лимиты: `AI_USER_DAILY_CALLS`, `AI_GLOBAL_DAILY_CALLS`.

## Разработка

```bash
uv sync                 # зависимости из uv.lock
make test-db            # временный PostgreSQL 16 на 127.0.0.1:55432
make test               # unit + интеграционные + e2e-тесты бота
make lint               # ruff + mypy (strict)
make test-db-stop
```

Для тестов с БД нужна переменная `TEST_PG_ADMIN_URL` (Makefile задаёт её для `make test-db`). Без неё тесты с БД пропускаются.

Миграции: `make migrate` (в Compose) или `uv run alembic upgrade head` с `MIGRATION_DATABASE_URL`.

## Устранение неполадок

| Симптом | Что проверить |
|---|---|
| `migrate` завершается с ошибкой аутентификации | Пароли в `.env` задаются только при первом создании тома. Если меняли их после — `docker compose down -v` (удалит данные!) или смените пароли ролей вручную. |
| Бот не отвечает | `make logs`; верный ли `BOT_TOKEN`; не запущен ли второй экземпляр с тем же токеном. |
| `webhook mode requires WEBHOOK_SECRET` | Задайте секрет длиной ≥ 32 символа. |
| Записи попадают «не в тот день» | Проверьте часовой пояс в ⚙️ Настройках. |
| ИИ-кнопки нет | ИИ выключен (`AI_PROVIDER=disabled`) или пользователь не дал согласие. |
