# РИТМ — питание и тренировки

**Еда. Движение. Твой ритм.** · Telegram: [@ritmappbot](https://t.me/ritmappbot)

Самостоятельно размещаемый Telegram-бот: дневник питания и тренировок для нескольких пользователей. Записи каждого пользователя изолированы кодом и row-level security в PostgreSQL. Интерфейс на русском (по умолчанию) и английском. Бренд задаётся настройками (`APP_NAME`), а не зашит в код.

РИТМ — дневник и помощник в привычках, а не врач. Он не ставит диагнозов и не рассчитывает «норму» автоматически.

## Что умеет (P1)

**Питание**
- Запись текстом, фото или голосом → **редактируемый черновик** → подтверждение → сохранение. ИИ ничего не сохраняет сам.
- Без ИИ работает разбор «овсянка 100 г, молоко 250 мл, банан»; калорийность берётся из ваших продуктов.
- Свои продукты с этикетки (на 100 г), избранное, сохранённые блюда, рецепты с выходом готового блюда и долей порции, «как вчера на завтрак».
- Неизвестное количество или калорийность никогда не превращаются в ноль. Оценки ИИ и примерные граммы помечены.

**Тренировки**
- Любые виды активности без миграций: готовые схемы (силовая, плавание, эндуро/мотокросс, мотопрогулка) и собственный конструктор полей.
- Шаблоны с блоками: разминка, основная часть, техника, интервалы, заминка; подходы, вес, повторы, дистанции, отдых.
- Несколько программ одновременно, планирование по дням недели.
- Запись по плану: цели показываются, факт вводится отдельно.
- Запись текстом: «жим 60 кг 10 10 8, тяга блока 70 кг 12 12 10».
- Импорт CSV из Strong.

**Прочее**
- «Мой день»: КБЖУ против ваших целей, тренировки, план, вес. «История»: вес, питание, тренировки, сводка по видам.
- Напоминания с часовым поясом, тихими часами и кнопкой «отложить».
- Экспорт своих данных (JSON) и удаление аккаунта.

Что проверено и что нет — в [docs/STATUS.md](docs/STATUS.md).

## Установка на Windows 11 (Docker Desktop)

Подробно, включая автозапуск и бэкапы, — в [docs/OPERATIONS.md](docs/OPERATIONS.md). Коротко:

```powershell
git clone -b claude/new-session-eumnaa https://github.com/dekks4213/MYNEWPROJECT.git C:\ritm
cd C:\ritm
copy .env.example .env
notepad .env        # пароли, BOT_TOKEN, при желании GEMINI_API_KEY и AI_PROVIDER=gemini
docker compose up -d --build
docker compose logs -f bot
```

Режим по умолчанию — polling: входящие порты, домен и HTTPS не нужны. Порт базы наружу не публикуется.

## ИИ (необязательно)

- `AI_PROVIDER=gemini`, `GEMINI_API_KEY`.
- Проверенные модели: `GEMINI_MODEL=gemini-3.5-flash-lite` для текста, `GEMINI_MEDIA_MODEL=gemini-3.5-flash` для фото и голоса.
- При старте бот проверяет доступность моделей. Если модель недоступна, ИИ отключается, а ручной режим продолжает работать.
- Лимиты на пользователя и глобальный: `AI_USER_DAILY_CALLS`, `AI_USER_DAILY_MEDIA_CALLS`, `AI_GLOBAL_DAILY_CALLS`.
- Пробный вызов: `uv run python scripts/smoke_gemini.py` (не больше 7 вызовов).
- Пользователь отдельно разрешает ИИ для текста и для фото/голоса. Метаданные фото удаляются до отправки.

## Разработка

```bash
uv sync
make test-db && make test     # unit + PostgreSQL-интеграция + e2e бота
make lint                     # ruff + mypy --strict
make test-db-stop
```

Тесты с БД требуют `TEST_PG_ADMIN_URL`; без него они пропускаются. Живой тест Gemini запускается только явно: `RITM_LIVE_GEMINI=1` (см. `tests/test_live_gemini.py`).

## Устранение неполадок

| Симптом | Что проверить |
|---|---|
| `migrate` падает на аутентификации | Пароли из `.env` применяются только при первом создании тома БД. |
| Бот не отвечает | `docker compose logs bot`; верный ли `BOT_TOKEN`; не запущен ли второй экземпляр с тем же токеном. |
| «ИИ сейчас выключен» | `AI_PROVIDER`, ключ, модель; в логах строка `ai provider ... ok` или причина отключения. |
| Записи попадают не в тот день | Часовой пояс в ⚙️ Настройках. |
| Напоминание не пришло | Включено ли; тихие часы; бот не заблокирован пользователем (тогда напоминания выключаются). |
